# Sentinel

Self-hosted officer of the watch: review requests sorted into lanes, your own PRs by what they wait for, the PRs you approved followed until they have landed (merged + post-merge checks green), provider status pages, the Claude Code sessions running on the host filed under their tickets (Sessions), optional Cycle objectives, an optional tech watch (Lookout) — local Docker, web UI on `localhost:8300`, Web Push, optional Claude agents through a host bridge and a Claude Code mod reading `/api/summary`.

**Design (14/10/2026): an inbox, one item at a time.** Sidebar (Inbox, Sessions, Cycle, Watch, Lookout, the status light, Settings) + list pane + detail pane, like a native macOS app at night: four surface steps (`--bg` → `--pane-3`) and hairline shadows for depth, system font (SF Pro), SF Mono for refs and diffs, 8–12 px radius. Colour says what something is: blue = waits on you / selection / primary action, red = broke, orange = needs a look, green = good news, terracotta = Claude. The list has three tabs: **Priority** (monitoring alerts, reviews for you, follow-up problems, your PRs one row per cause), **Later** (snoozed, team requests in grace, bumps, status pages, reminders, what is landing after your approval, your PRs waiting on others), **Done**. Two triage actions only: **Done** (ack until it changes) and **Later** (snooze until tomorrow 9:00). Keyboard: `↑↓`/`j k`, `E`, `L`, `⏎`. No gradient beyond the logo, no emoji, no CSS framework. Tokens at the top of `static/style.css` — keep new UI inside them.

## Stack

- **Backend**: Flask 3 + Gunicorn (python:3.12-slim) — **exactly 1 worker** (`-w 1 --threads 8`): APScheduler runs in-process, more workers = duplicated jobs
- **Frontend**: Jinja2 + HTMX 2 (CDN with SRI) + Google Fonts, no build step
- **State**: SQLite `/data/sentinel.db` (WAL), `./data/` volume
- **Notifications**: Web Push (pywebpush + VAPID), service worker `sw.js` served at the root

## Triage model (engine.py)

Every `WatchedItem` has a **lane** (where it shows: `you`, `team`, `deps`, `mine`, `followup`, `incident`, `watch`, `cycle`, `health`) and an **urgency**:
- `now` → pushed when it appears, again when its fingerprint changes after an ack
- `later` → pushed only if still pending after `triage.team_grace_minutes` (`promote_due()`, every minute) — team review requests; resolved meanwhile = never pushed
- `quiet` → never pushed (bumps, drafts, maintenance, reminders)

"Needs you" = `db.ATTENTION`: pending and (`now`, or `later` already notified). Badges count **decisions** in the inbox lanes (`main.INBOX`: watch, you, team, followup, mine — health is the sidebar light, cycle its tab, incidents wait in Later) (`main._units`): every item, except your own PRs which count once per cause (`_mine_groups`: action + first failing CI family). Your PRs approved and green (`merge`) are listed, never pushed (`my_prs.LISTED`). A post-merge failure whose follow-up run says `unrelated` is cleared (`_clear_by_claude`): it leaves "needs you" for Later.

State machine: `pending` → `acked` (re-opens when the fingerprint changes unless `ack_forever`, set by older versions only) / `snoozed` (`wake_snoozed()`, quiet items wake silently) → absent from `MISSES` (2) fetches in a row = `resolved` (`items.missed`; GitHub search drops PRs for a poll now and then — 17 PRs were re-pushed within 30 min before this) → reappearance = fresh cycle (`first_seen` reset). Fingerprints encode what should re-open an ack: `updatedAt` for direct reviews, the constant `team` for team requests (a team PR moving is still not yours), the target version for bumps, the action (+ failing CI families) for your PRs, a `days // stale_days` bucket for stuck approvals.

Guards: `promote_due()` and `wake_snoozed()` skip items missing from the last poll (`missed > 0`). More than `STORM` (3) notifications from one pass → one summary push. **First pass of a source** (no `seeded` flag in `watcher_state`) records without pushing and re-baselines old rows (`notified_at = first_seen`, acks moved to the new fingerprint) — an upgrade that changes fingerprints must not resurface everything. `promote_due()` ignores sources not seeded yet. `check_health()`: `db.record_run()` keeps `error_since` per source; every source failing longer than `triage.health_minutes` → **one** item `sources` (lane health, constant fingerprint: one push per outage — they fail together, 40 per-source pushes in two days before) shown as the sidebar light (`_status`).

Sources named from the config (`statuspage:<name>`, `grafana:<uid>[-<vars hash>]`) that left it are retired at start (`engine.retire`): their items resolved, their state dropped — a removed link must not wait forever or keep a failure lit.

## Follow-up (followup.py)

One GraphQL call: `reviewed-by:<login> -author:<login> author:app/<bot>…` open + closed within `window_days`, with the merge commit's check runs and its **first parent's** check runs. Post-merge checks = check runs whose workflow event is not `merge_group`/`pull_request*` + commit statuses. Stage: `waiting` (blocker, worst first: dismissed > conflicts > ci failing > changes requested > review required > draft > ci running > ready) · `checking` (pending, or merged < 30 min with nothing yet) · `failed` · `inherited` (every failing check was already failing before: on the parent commit, or — when the job did not run there, `paths` filters — in the previous run of its workflow on the base branch, `evidence.previous_outcome`, cached) · cancelled runs are neutral (`concurrency:` supersedes them) · `reverted` (a cross-referenced PR titled "Revert…") · `landed` · `no checks` · `closed`. Items: dismissed, stuck (`waiting_days >= stale_days`), failed, reverted. A `failed` PR merged less than `AUTO_INVESTIGATE_HOURS` (48) ago gets one `followup` agent run per merge commit — never on the source's first pass; older ones keep the Investigate button (no surprise push about the past). Pages read the stages through `main._followup_view`: `inherited` + failed-and-cleared-by-Claude = section "not yours", and every count (inbox, Later, badge) comes from it or from the engine items. `followup.cleared()` is the one clearing rule: verdict `unrelated` AND no open failure that passed right before the merge AND every open failure among the checks whose logs the run read (`investigated` in its context; an older run without it clears nothing) — a verdict alone can be steered, and a check that failed after the investigation was never judged. `_investigate` asks again when the set of failing checks changes (`settled(failing=…)`). A previous run GitHub could not return (`unknown`) keeps the last refresh's answer (`known`, absent included), else waits in `checking` for `UNKNOWN_MINUTES` (60, `unknown_since`) and then alerts as "absent" — no alarm on a hiccup, no silence when the API stays down. `previous_outcome` lists runs created before the failed one (`created=<…`), same event only, and caches only failure/success answers.

## Dependency bumps (deps.py)

A review request whose author is a Bot and whose title parses as a bump (or carries a renovate/dependencies label) goes to lane `deps`. The PR body is fetched once per (PR, title) for the update table: type (major > minor > patch), from → to. `pending_groups()` groups pending bump items by `name@to`; **Approve N green** (`POST /api/deps/approve {key, ids: "id:sha,…"}`) reviews only the PRs the page showed, still `approvable()` (green, not draft, not conflicting), whose head is still the sha the page showed (`github_pr.head_sha`), pinned with `commit_id` — the rest is reported back. `precheck()` (every 5 min) queues one `precheck` run per group (subject `deps:<name>@<to>`), PR URLs of every repo at once, and again when the set of PRs changes (`settled(urls=…)`).

## Claude agents (agents.py + contrib/claude-bridge)

`agent_runs` = one row per (subject, mode), subject = `owner/repo#n` or `deps:<key>`; `queue_run` re-queues, `tick()` (every 10 s) starts up to `agents.concurrency` runs in threads → `POST {bridge}/run {mode, url, urls, context}` with `Authorization: Bearer CLAUDE_BRIDGE_TOKEN`. Automatic modes obey `agents.precheck|followup` and `max_runs_per_day`, retry a failed run after an hour up to `MAX_ATTEMPTS` (3, `attempts` column); on-demand ones never do, and reset attempts. Their context is a callable (`deps.context`, `followup.context`): the GitHub fetches of the material only happen when a run is actually queued. `check_bridge()` (every 2 min) records `claude-bridge` in `watcher_state`: a bridge that does not answer, or an older one without this version's modes, becomes a health item. The page only names a subject: `_agent_target()` rebuilds URL and context from Sentinel's own data. Prompts start with `Verdict: <token>` (English tokens whatever `BRIDGE_LANG`): `agents.verdict()` reads the **first line only** (a verdict quoted from a log further down must not count) → (token, tone), `first_finding()` for rows, `summary_line()` for pushes. A finished `followup` run pushes its verdict (`_announce`). Every run passes `--setting-sources user`: the project/local settings of `BRIDGE_CWD` carry their own allow rules, which **add** to `--allowedTools` (verified 12/10/2026: an allowed `Bash(tee:*)` wrote a file). **Reading ahead** (`insight.refresh()`, every 5 min): `brief` per review request (subject `owner/repo#n`, settled on `head`), `whyred` per first failing CI family of your PRs (subject `why:<family>`, settled on the sorted `repo#n@head` list), `asks` per PR of yours with changes requested or open threads (subject `asks:owner/repo#n`, settled on changes_by + unresolved count); verdicts land on the list rows (`list_macros.claude_tag`) and in the detail. **Lookout** (below): `scout` and `assess` (subject `lookout`), `dig` on demand (subject `lookout:<id>`, `_agent_target` → `lookout.target`). `ON_FINISH[mode](run, output)` runs **before** the run reads done (lookout: its rows are still claimed while they are written); raising fails the run. `context["profile"]` is sent as the top-level `profile` — the reader's own words, the only text the bridge puts outside the fence. Toolsets: `precheck`, `followup`, `brief`, `whyred`, `asks`, `scout`, `assess`, `dig` = **no tool** (`--tools ""`), the material (built by `evidence.py`) arrives in `context` and the bridge fences **all** of it between BEGIN/END MATERIAL as untrusted (a custom prompt without `{context}` gets it appended); `deep` = named read-only commands, no `gh api` (`-f` POSTs, `-X` can follow any prefix), no WebFetch, offered only on PRs whose author is not a Bot. The bridge refuses non-local Host headers, runs nothing without `BRIDGE_TOKEN`, and `/healthz` reports `api` (5) and `token`: `check_bridge()` flags an older bridge or a missing token. The daily cap is one counter of automatic queues, retries and re-runs included (`agents.used_today`, `watcher_state` agents/day+count). The fence markers carry a per-run nonce (`BEGIN MATERIAL <nonce>`): the material cannot fake its end. `deep` may only `git fetch origin` and its Read tool refuses `.env`, `.mcp.json`, keys, `~/.ssh`, `~/.aws`, `~/.config` (a shell `cat` stays possible: a fence, not a vault — the remaining exfiltration path is a `gh … -R <host>` lookup). `reviews` (old table) is migrated into `agent_runs` at startup.

## Lookout (lookout.py)

`collect()` (every `collect_minutes`) runs `lookout_sources.jobs()` — one read per feed, trending language and repository (Reddit: one read for every subreddit, `r/a+b`; a second read right after gets a 429) — into `lookout`, one row per `canonical()` key: a repository is `github:owner/repo` whichever page of it is shared, other links lose `www.` and tracking parameters; a known key gets the new mention (`sources` JSON: source → discussion, points, comments), and a `dropped` one goes back to the scout when a source it was not seen on mentions it — traction shows as a second source. Only http(s) links are stored (rows render them as `href`). Per-source status lives in `watcher_state` (`lookout`, `source:<name>`) without `error_since`: a failing feed shows at the bottom of the page, never as a health item.

`advance()` (every 2 min, a few queries when idle): `_recover()` (rows claimed by a run no longer queued/running go back: `scouting` → `new`, `assessing` → `kept`), `_scout()` (all `new` rows up to `batch`, oldest first, at most every `scout_hours` — immediately when a full batch waits after a success), `_assess()` (`kept` rows by `assess_batch`, material fetched in the context callable: repository facts + README through `github.rest`, an article through `page_text`, a release's notes; `facts` saved for the page), `digest()`, `_forget()`. `_ready()` gates both: a failed run retries after an hour up to `agents.MAX_ATTEMPTS`, then waits `scout_hours` — a broken prompt must not eat the daily cap the other modes share. `apply_scout` / `apply_assess` (hooked through `agents.ON_FINISH`) need their verdict line (`scouted` / `assessed`) or nothing moves and the run fails; unknown ids are ignored, a row left out of an assessment is assessed without a score (never shown). Releases (`releases` source: minor/major, or a patch whose notes mention security/CVE) skip the scout. A **find** = assessed, score ≥ `threshold`, verdict not `skip` (`lookout.finds()`). Feedback (`useful`, `noise`, `known`, `try`) goes back into both prompts (last 40). The page follows the digest: *New since the last digest*, *In the last digest* (what Monday's push announced), *Earlier* (collapsed); *To try* = feedback `try` whatever the score (a threshold raised later does not empty it); *Filtered out* = the week's near misses (assessed under the threshold) first, then the most upvoted drops. Parsing accepts list items, numbers and bold (`1. **#12** — …`). `digest()`: once per `last_slot(digest)` (local `TZ`), the finds assessed in the week before the slot, one push, none without finds; the slot is recorded either way. `_forget()`: rows without feedback older than `keep_days`.

`page_text()` reads public addresses only (`public()`: every resolved address `is_global`), follows redirects itself and checks each hop, HTML only, 1.5 MB and 30 s max (a server dripping bytes must not hold the job), the `<main>`/`<article>` text when there is enough of it; a page that reads as a few words (Reddit's app shell) falls back to the summary — a self post's text is stored at collection. DNS rebinding can still beat `public()`; nothing leaves anyway: no tool, and `md.render` drops images. The Lookout prompts leave `{url}` out: a find's link is feed text, it travels in the fence like the rest — only `profile` is outside. The trending source is a third-party RSS mirror of github.com/trending (no API): when it breaks, its rows show as failing sources.

## Sessions (sessions.py + bridge `GET /sessions`)

**The context advisor owns a session's story and figures.** `contrib/claude-code-context` writes, on every refresh of its status line and at once on `/clear` or a resume (a new session id), `<CLAUDE_CONFIG_DIR>/context-advisor/<session id>.json` (`published()` in its core: story, pinned, project, tokens, answeredAt, cold, advise `cold|handoff|''`, nextUsd, freshUsd, its handoff command — `/handoff`, or `/context-handoff` when another plugin holds that name, a skill of the same name included); a session gets back the story published for it, when resumed or when the mod starts again (a reload or a respawn fires `session.start` with the module's state reset); `CONTEXT_STORY` links a session nothing was published for, as `/ticket` would (`pinned`). `contrib/claude-code-context/tests/published.ts` is the format: the advisor's test checks `published()` against it, `test_sessions.py` reads it. Sentinel shows that file as is — no story rule, threshold or price of its own — through `sessions._context()`: a field not written the way the advisor writes it reads as absent (its handoff command is typed into a live session). A session without the advisor lists without story or size, never as *answered* (no word on its cache).

The bridge: `claude agents --json` (Claude Code's list for scripts: id, pid, name like `dev-9a`, status idle/busy/waiting, waitingFor; a failure is a 500 with its message, never an empty list), + the console (tmux pane whose shell is — or is the parent of — the pid; a console not listed yet = `starting`), + the title (last `ai-title` in the last MiB of the transcript), + the advisor's file; advisor files older than 7 days are deleted (the advisor cannot). `POST /console` with `story` → `CONTEXT_STORY` in the session's environment. `POST /console/end` returns once the console's Claude has exited (10 s max): it takes seconds, and a session seen meanwhile reads as one in another terminal. `/clear` keeps the pid and changes the session id: the row stays on its console.

`board()` files the sessions (`live()`, 3 s cache) under the cycle's stories (`cycle.load()`: each big rock's epics, then the run) by the advisor's story — a console named `sc-N` (or `sc-N-xxxx`) is that ticket's until the advisor speaks —, then your started stories without a session; your unstarted ones fold (`later`); the rest is *Off cycle*. State: waiting > working/starting > done (idle, answered, cache warm) > idle (cache cold, or nothing answered since a `/clear`); the advice puts the size on the row. Row keys `console:<name>` / `session:<id>` / `story:<id>`; `_find` falls back from a ticket's key (`story:N`, `console:sc-N[-xxxx]`) to the row that now carries it (picked up, or its console ended). The detail: a console → `data-attach` (console.js attaches on `htmx:afterSwap` of `#detail` without taking the keyboard — the list keeps ↑↓⏎ until you click in —, disposes on the next swap); a session elsewhere → read-only; a ticket → `shortcut.story` (state, open PRs, last comment whose first line says Handoff, else the last) + **Pick up** (`POST /api/sessions/start`: console `sc-N` linked to it — `sc-N-xxxx` when `sc-N` has moved on to another ticket —, prompt `sessions.resume_prompt` or `RESUME_PROMPT`, `{story}` only). A console's pane asks Shortcut nothing. **New** (`/api/sessions/new`): console named after the task's first words. Started → `HX-Trigger-After-Settle: select-key`, the next list poll selects it. **Start fresh** types the advisor's handoff command without Enter (`data-term-type`). Badge = sessions `waiting`; the nav asks the bridge on full pages only.

## API for the Claude Code mod

`GET /api/summary?since=<notification id>` → `attention`, per-section `counts`, `landing` (follow-up stages), up to 25 items needing you (id, lane, ref, title, url, why, claude headline), notifications after `since`, `seq`. Item actions answer JSON unless the request comes from HTMX (`_done()`: the list, retargeted to `#list`, + `HX-Trigger-After-Settle: acted` so the page selects the next row): `POST /api/items/<id>/ack|unack|snooze|unsnooze` (snooze `duration`, default `tomorrow`), `POST /api/items/bulk {ids, action: ack|snooze}`.

## Adding a watcher

1 file in `watchers/` (class with `name`, `interval_seconds`, `fetch()` returning `WatchedItem`s with lane + urgency + a fingerprint that changes only when an ack should re-open), register it in `build_watchers()`, 1 block in `config.yaml`. Diff, state, grace, notifications are already handled. A source computing its own state (like my_prs/followup) calls `engine.process(name, items)` after `db.record_run(name)`.

## Conventions

- Commits: Conventional Commits, no Claude/Co-Authored-By signature
- DB timestamps: UTC ISO `%Y-%m-%dT%H:%M:%SZ`, local display via `localdt`, ages via `age`
- No application auth: bind `127.0.0.1:8300` only
- Public repo: no org names, logins or internal project names in code, docs, examples or screenshots (config.yaml/.env/data are gitignored; screenshots only from fake data)

## Gotchas

- Subscribe to push from `http://localhost:8300` (never `127.0.0.1`) and with Chrome/Firefox (Safari is finicky)
- `vapid_claims`: pass a fresh dict to every `webpush()` call (pywebpush mutates it)
- Never call a `db.*` helper that opens its own connection while holding a write transaction (`with db.connect() as conn:` after a write): the second connection waits on the lock for `busy_timeout` then fails — read `watcher_state` before the transaction, write it after
- Polled regions (`#list` every 20 s, `#watchers`, `#cycle`): `app.js` skips the swap when the HTML is byte-identical, otherwise keeps the list scroll, every open `<details id>` and the selected row (`data-key`). The detail pane is never polled — only Claude blocks poll themselves while a run works. Give any new `<details>` an id or it closes on the next poll
- `app/` is COPYed into the image, not bind-mounted: a template or Python change needs `docker compose up -d --build`
- Never open `data/sentinel.db` from the host while the container runs (WAL across the bind mount → `disk I/O error` in the app): `docker compose exec` or the API
- Jinja: a dict key named like a dict method (`items`, `keys`) resolves to the method — use another key (sections use `rows`)
- Bridge plist edits: `launchctl bootout` then `bootstrap` (`kickstart -k` keeps the old EnvironmentVariables). The bridge is a separate process: an upgrade of the app needs a bridge restart too, `check_bridge()` flags an old one
- Console: the page names the alert, Sentinel writes the prompt (`watch_views.api_zabbix_console`), the bridge passes it to the shell as `SENTINEL_PROMPT` (expanded, never parsed) and strips `BRIDGE_*` from the tmux server's environment. The WebSocket (`/console/ws`) takes no token: a ticket from `POST /console` (once, 60 s) + an Origin in `BRIDGE_ORIGINS` — keep both. `app.js` leaves every key typed in `#console` or a `.console-term` to the terminal (Escape included). A `.console-term` is `content-box`: xterm's fit reads the host's computed height as its room. `main.not_in_a_frame` (X-Frame-Options + frame-ancestors) is what stops a framing page from clicking Claude and typing for you — keep it. Zabbix fields enter the prompt through `watch_views._field` (one printable line, 300 chars)
- A second bridge (a test instance) shares `tmux -L sentinel` with the first: it lists, attaches to and ends the same consoles
- `#detail` takes only the selected row's answer (`app.js` beforeSwap guard): a button filling the pane on its own (Sessions' New) carries `data-unselect`. `rows()` skips rows in a closed `<details>` — not `offsetParent`, Chrome keeps it on `content-visibility: hidden` content
- Rendered markdown (Claude verdicts, GitHub comments) goes through `md.render` → nh3 allowlist: never mark untrusted HTML `|safe` any other way
